# 货币整数列迁移（v55）

本次移除四个已经有整数对应列的浮点镜像：`users.balance`、`api_keys.budget`、`api_keys.used_cost`、`usage_logs.cost`。`*_units` 是唯一持久化金额，单位为 10⁻⁹ 元。价格、折扣和支付订单金额不属于这四个账本镜像，不在本次删列范围内。

API 的 `balance`、`budget`、`used_cost`、`cost` 字段继续提供十进制展示值，由整数列派生。汇总先累计整数，再转换展示值。运行时不再从浮点镜像回退、双读或双写。旧浮点镜像漂移指标 `airoute_billing_wallet_drift_units` 随镜像一起移除；账本对账、审计差额和整数钱包总额指标继续提供。

## 迁移行为

迁移 v55 在同一个事务中完成回填和四列删除。非零整数金额优先，保留负余额；只将整数为零、浮点非零的历史行按四舍五入转换为整数。不能安全转换为 int64 的金额会使迁移报错并回滚，SQLite 不得通过截断溢出继续启动。

事务中的任一回填或删列失败，所有表和数据一并回滚。迁移成功但版本记录前崩溃时，再次执行会跳过已移除的列。新建数据库也执行这一步，最终结构与升级数据库相同。

## 升级操作

这次删列不支持新旧网关实例同时访问同一数据库。旧二进制仍引用镜像列，因此不能采用通常的双节点滚动升级。

1. 在数据库备份的副本上完成迁移和恢复演练，保留可用的旧镜像。
2. 暂停入口流量，等待流式请求和异步记账完成，停止所有网关写入者。
3. 对 PostgreSQL 做完整 `pg_dump`；SQLite 在关闭写入者后使用数据库备份接口备份，包含完整数据库状态。
4. 用新版本启动一个节点完成 v55，确认金额和账本总额，再启动其余新版本节点。
5. 检查健康探针、钱包/密钥查询、付费请求及其审计记录，然后恢复流量。

实施前后对比四列整数的行数、总额和关键账户余额；对于历史浮点独有值，应将预期回填金额单独计入对比。不要将备份、凭据或数据库文件加入 Git。

## 回滚

优先在停止全部写入者后恢复升级前备份，再切回已保留的旧镜像。如果需要保留升级后发生的整数记账，PostgreSQL 可在完整备份后执行 [回滚脚本](../scripts/rollback-money-mirrors-postgres.sql)，由当前整数金额恢复旧二进制需要的四列，再启动旧版本。脚本也删除 v55 的版本记录，后续重新升级会重新执行迁移。脚本仅供明确回滚时使用，不是正常运行时兼容层。

SQLite 的回滚使用备份恢复；不要在运行中手工添加展示列或直接拷贝仍有写入者的 WAL 数据库。

## 验证

- SQLite：新建数据库无浮点镜像，历史金额回填、整数优先、负值保留、重放幂等、溢出时事务回滚。
- PostgreSQL：同一组迁移和回滚断言、显式回滚脚本恢复演练，以及真实结算/预授权/账本归档集成测试。
- 日期窗口费用使用 UTC 日/月边界，同时提供近 24 小时和前 24 小时费用；租户和密钥筛选与原概览相同。
