## 3. 数据面行为

- 请求进入：认证中间件在钱包预扣前做预算预检；disable 规则耗尽返回 `402 budget_exceeded`。预算表缺失时 fail-open 并限流告警。
- 请求完成：计费后异步 `RecordSpend` 累加计数器、写阈值事件、异步通知；30s `Flush` 回写 `budgets.used_units`。
- 成本：若通道+模型配置了供应商价目，`usage_logs.cost_basis_units` 写入实际成本；未配置保持 NULL。每次请求同时记录稳定 `channel_id`，成本趋势通过 `usage_daily` 按需重建。
- 预算：30s 回写计数；每 6h 从 `usage_logs` 重算 active 预算，修正重启/漏写造成的漂移。
- 钱包：结算扣费写 `charge`；充值/兑换/管理调整写对应类型；账本 ref 幂等。

## 5. 回滚与运维

- 迁移前备份数据库；v30–v37 均为增量迁移。
- v34 删除旧 `*_nano` 列前已做一致性校验；如需回滚只能恢复备份（旧列不再被代码读取）。
- 预算/钱包/成本表缺失不会阻断数据面：预算 fail-open、账本写入跳过、成本列保持 NULL；但对应 API/UI 会报错。
- 告警通道可选：`GATEWAY_ALERT_WEBHOOK_URL`、`_DINGTALK_URL`、`_FEISHU_URL`、`_WECOM_URL`、`GATEWAY_ALERT_EMAIL_TO`（邮件复用 `SMTP_*`）。

## 6. 已知限制与后续

1. **`usage_daily` 为按需/定时重建**：按日趋势接口会为请求区间重建近期日桶；更长历史需要调度任务预热，否则首次查询较慢。
2. **日桶按 UTC 切分**：`usage_daily.day` 使用写入时的 UTC 日期；展示时按 UTC 日期解释。
3. **账本-余额对账任务是后续运维增强**：v1.1 通过同事务写入与测试保证一致性；独立巡检任务未做。
4. **单机回退**：Redis 不可用时预算计数退回进程内存，多副本下为近似值。
5. **历史成本未知**：v37 之前写入的 `usage_logs.cost_basis_units` 为 NULL，成本分析会将其计入“未定价请求”。
6. **通道 ID 回填依赖唯一通道名**：找不到通道的历史行保持 NULL；通道重命名后旧行仍指向旧 ID（由名称唯一性保证回填正确）。

自检发现并修复的问题：

- **钱包并发丢更新**：`UpdateUserBalance` 原为“读旧值-写新值”，与结算扣费并发时可能丢失一次扣款；已改为原子 `UPDATE ... RETURNING`，并在扣费/精确设置前锁定用户行（PG `FOR UPDATE`，SQLite no-op 写锁）。修复后重建集群并复验账本偏差为 0。
- **v38 历史夹具兼容**：缺少 `channels` 表的旧迁移夹具会在回填时失败；已加表存在探测后跳过。
- **日桶边界**：`usage_daily` 刷新结束边界曾带微秒，恰好 00:00:00 的行会漏到前一天；改为秒级排他边界。
