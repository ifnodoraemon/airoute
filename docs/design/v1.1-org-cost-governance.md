## 0. 已定决策（实施约束）

| 决策 | 结论 | 影响 |
|---|---|---|
| **结算口径** | **售价口径 + 成本侧毛利**：部门账单按目录价 × 分组倍率；供应商成本只用于毛利、渠道比价与成本分析 | 账单/预算基于 `usage_logs.cost`；新增 `cost_basis_units` 只记账不扣款 |
| **付费模式** | **先预付，后付排 v1.2**：v1.1 沿用钱包预付 + 组织预算；授信额度、月结、收款登记后续 | 不引入 `credit_limit` / 应收状态机 |
| **组织层级** | **单位 / 部门 / 项目 三层树** | `orgs` 带 `parent_id` + 物化路径；配额与账单按“就近继承” |
| **推广范围** | **本部门/条线先复制**；信创（离线包/国产库/国密）作为材料线并行 | v1.1 不把信创适配作为阻塞项 |
| **P0 提交** | 已按模块拆 5 个 commit：`6b9c4bb` / `538b39b` / `1042cdc` / `41d53a1` / `e07c753` | v1.1 从干净基线开始 |

## 1. 目标与非目标

**目标（v1.1 验收）**

1. 能创建“单位 → 部门 → 项目”组织树，用户与 API key 可归属到组织。
2. 每次请求的审计行带 `org_id`；控制台可按组织查看请求、token、费用。
3. 可配置组织/用户/key 三级预算（日/月/总额），到阈值发通知，到上限按策略停用。
4. 钱包每次资金变动都有流水，流水可按时间加总回当前余额。
5. 价目可批量导入/导出；供应商成本可维护，能看到按模型/渠道/组织的毛利。
6. 普通用户可在控制台看到自己的用量、配额水位与密钥健康度。

**非目标**

- 后付/授信/月结单（v1.2）
- 发票、税务、ERP/财务系统对接
- 语义缓存、智能路由（v1.4）
- 跨单位投标所需的信创适配（材料线单独推进）

## 2. 数据模型与迁移拆分

迁移保持“只加不删”，每个切片一个版本，避免一次大迁移触碰账本：

| 迁移 | 内容 | 切片 |
|---|---|---|
| **v30** | `orgs`、`org_memberships`、`users.org_id`、`api_keys.org_id`、`usage_logs.org_id`、`billing_settlements.org_id` + 回填 | M1 |
| **v31** | `budgets`、`budget_events` | M3 |
| **v32** | `wallet_transactions` + 期初流水回填 | M4 |

### 2.1 组织与归属（v30）

```sql
CREATE TABLE orgs (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  parent_id   INTEGER REFERENCES orgs(id),
  level       TEXT NOT NULL,              -- unit | department | project
  name        TEXT NOT NULL,
  code        TEXT NOT NULL UNIQUE,       -- 稳定业务编码
  path        TEXT NOT NULL,              -- 物化路径 '/1/4/9/'
  depth       INTEGER NOT NULL DEFAULT 0,
  status      TEXT NOT NULL DEFAULT 'active',
  created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at  DATETIME DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_orgs_parent ON orgs(parent_id);
CREATE INDEX idx_orgs_path   ON orgs(path);

CREATE TABLE org_memberships (
  org_id     INTEGER NOT NULL,
  user_id    INTEGER NOT NULL,
  role       TEXT NOT NULL DEFAULT 'member',  -- admin | member
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (org_id, user_id)
);

ALTER TABLE users               ADD COLUMN org_id INTEGER;
ALTER TABLE api_keys            ADD COLUMN org_id INTEGER;
ALTER TABLE usage_logs          ADD COLUMN org_id INTEGER;
ALTER TABLE billing_settlements ADD COLUMN org_id INTEGER;
```

- `path` 由服务端在创建/移动时维护；移动组织只改自身与子孙的 `path`，**历史审计的 `org_id` 不回溯**（归属按请求发生时的组织）。
- 根组织固定 `code='default'`、`level='unit'`，迁移时创建。

**回填规则（幂等）**

1. 创建根组织 `default`。
2. `users.org_id` 为空 → 根组织。
3. `api_keys.org_id` 为空 → 属主用户的 `org_id`（用户为空再落根）。
4. `usage_logs.org_id` 为空 → 通过 `api_key` 关联 `api_keys.org_id`，找不到落根。
5. `billing_settlements.org_id` 同理。
6. 新 key 创建时：默认取属主用户 `org_id`；管理员显式指定时以请求为准（v1.1 先做默认，不做跨组织授权）。

### 2.2 预算（v31）

```sql
CREATE TABLE budgets (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  scope_type   TEXT NOT NULL,      -- org | user | key
  scope_id     INTEGER NOT NULL,   -- orgs.id / users.id / api_keys.id
  period       TEXT NOT NULL,      -- daily | monthly | total
  amount_units BIGINT NOT NULL,
  used_units   BIGINT NOT NULL DEFAULT 0,
  action       TEXT NOT NULL DEFAULT 'notify',  -- notify | disable（degrade 预留）
  warn_percent INTEGER NOT NULL DEFAULT 80,
  status       TEXT NOT NULL DEFAULT 'active',
  period_start DATETIME,
  created_at   DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at   DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(scope_type, scope_id, period)
);

CREATE TABLE budget_events (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  budget_id    INTEGER NOT NULL,
  threshold    INTEGER NOT NULL,   -- 50 / 80 / 100
  used_units   BIGINT NOT NULL,
  amount_units BIGINT NOT NULL,
  action       TEXT NOT NULL,
  created_at   DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

**解析顺序**：`key` 显式预算 → 属主 `user` 预算 → 组织链上最近的有预算祖先 → 无预算（不拦截）。多周期同时命中时，最严格的动作生效（`disable` > `notify`）。

**计数一致性**：数据面读内存快照（随现有 10s 同步刷新）；单副本用原子计数，集群优先 Redis `INCRBY` + 周期回写 `budgets.used_units`；每日用 `usage_daily` 对账修正。允许 10s 级最终一致，文档明确。

### 2.3 钱包流水（v32）

```sql
CREATE TABLE wallet_transactions (
  id                  INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id             INTEGER NOT NULL,
  type                TEXT NOT NULL,  -- opening|recharge|redeem|charge|adjust|refund|reversal
  delta_units         BIGINT NOT NULL,
  balance_after_units BIGINT NOT NULL,
  operator            TEXT,
  reason              TEXT,
  ref_id              TEXT,           -- billing_id / order_no / 兑换码
  created_at          DATETIME DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_wallet_tx_user_created ON wallet_transactions(user_id, created_at);
CREATE UNIQUE INDEX uq_wallet_tx_ref ON wallet_transactions(user_id, type, ref_id)
  WHERE ref_id IS NOT NULL AND ref_id <> '';
```

- 扣款/结算/充值/兑换/调账与余额更新**同一事务**写入；`ref_id` 唯一键保证重投递不重复记账。
- 迁移为每个用户写一条 `opening` 期初流水（当前余额），保证“流水加总 = 余额”。
- 现有 `wallet_deduct`、结算、Stripe、兑换、管理员调额全部接入。

### 2.4 成本侧与分析（v33）

```sql
CREATE TABLE supplier_costs (
  id               INTEGER PRIMARY KEY AUTOINCREMENT,
  channel_id       INTEGER NOT NULL,
  model            TEXT NOT NULL,
  prompt_price     DOUBLE NOT NULL DEFAULT 0,   -- 每 1M token，CNY
  completion_price DOUBLE NOT NULL DEFAULT 0,
  cache_read_price DOUBLE NOT NULL DEFAULT 0,
  fixed_price      DOUBLE NOT NULL DEFAULT 0,
  currency         TEXT NOT NULL DEFAULT 'CNY',
  created_at       DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at       DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(channel_id, model)
);

ALTER TABLE usage_logs ADD COLUMN cost_basis_units BIGINT;  -- NULL = 成本未配置
ALTER TABLE usage_logs ADD COLUMN channel_id INTEGER;

CREATE TABLE usage_daily (
  day                 TEXT NOT NULL,      -- YYYY-MM-DD
  org_id              INTEGER NOT NULL DEFAULT 0,
  model               TEXT NOT NULL,
  channel             TEXT NOT NULL,
  requests            BIGINT NOT NULL DEFAULT 0,
  success             BIGINT NOT NULL DEFAULT 0,
  prompt_tokens       BIGINT NOT NULL DEFAULT 0,
  completion_tokens   BIGINT NOT NULL DEFAULT 0,
  cached_tokens       BIGINT NOT NULL DEFAULT 0,
  cost_units          BIGINT NOT NULL DEFAULT 0,
  cost_basis_units    BIGINT NOT NULL DEFAULT 0,
  PRIMARY KEY (day, org_id, model, channel)
);
```

- 成本只记账、不参与钱包扣款；`NULL cost_basis` 表示“未配置成本”，报表单独展示“成本覆盖率”，绝不默认 0 制造假毛利。
- `channel_id` 由 dispatcher 注入（响应与流式事件加内部字段），审计行落库；历史行按渠道名回填，重名渠道留空并告警。
- `usage_daily` 由后台 worker 按小时增量聚合，支持 30/90 天查询；日切后重算幂等（`INSERT ... ON CONFLICT DO UPDATE`）。

## 3. 请求链路改动

1. `AuthMiddleware` 解析 key 时把 `org_id`、属主、预算上下文写入 gin context；内存快照新增组织与预算字段。
2. 准入顺序：key 状态 → key 预算 → 用户/组织预算 → 钱包余额 → 在途额度。预算拒绝返回 `402 budget_exceeded`（disable）或放行并写 `X-Airoute-Budget-Warning`（notify）。
3. `RecordUsage` 从 context 取 `org_id`/`channel_id`，落审计；结算事务同步写钱包流水；异步更新预算计数。
4. 成本核算在响应后执行（渠道已知），写入 `cost_basis_units`；失败不影响收款。

## 5. 迁移、回滚与升级

- 所有迁移只加列/加表；旧二进制可忽略新列，支持滚动升级期间新旧副本共存（新副本先迁移）。
- 回填按批处理（每 5000 行），失败可重入；迁移版本记录成功后才落库（沿用现有 runner）。
- 回滚策略：代码回滚到上一版本即可；新增表/列留在库中不影响旧版本。不提供破坏性 down migration。
- 迁移前 `make check-deploy-drift` 与数据库备份（沿用发布流程）。

## 6. 测试与验收

| 层面 | 用例 |
|---|---|
| 迁移 | SQLite 内存库跑 v30–v33；重复执行幂等；回填后所有用户/key/审计都有 `org_id`；根组织唯一 |
| 归属 | 新 key 继承用户组织；显式指定优先；历史行回填正确；组织移动不回溯历史 |
| 预算 | key→用户→组织解析；多周期最严格动作；80% 事件只发一次；disable 返回 402；计数对账修正 |
| 流水 | 扣款/充值/兑换/调账同事务；`ref_id` 重复不重复记账；流水加总 = 余额；期初流水正确 |
| 成本 | 渠道+模型成本匹配；未配置为 NULL；毛利 = 售价 - 成本；成本覆盖率报表 |
| 分析 | `usage_daily` 聚合与明细一致；日切重算幂等；组织/模型/渠道分组 |
| 导入 | dry-run 差异预览；非法行定位；事务提交/回滚；操作审计 |
| 前端 | 组织树、预算表单、流水表、成本图表、自助门户；lint/test/build |
| 回归 | `go vet ./...`、`go test -race ./...`、既有 E2E |

**运营指标**：组织覆盖率、预算配置数、告警到达率、流水可加总率、成本覆盖率、月结准备度。

## 8. 风险与待定

| 风险 | 缓解 |
|---|---|
| 回填触碰 50k+ 审计行 | 分批 + 索引 + 可重入；先备份；在预发验证耗时 |
| 预算计数多副本不一致 | Redis 共享计数 + 周期回写 + 每日对账；10s 最终一致写入文档 |
| `channel_id` 历史回填遇重名渠道 | 以名称唯一约束为前提；重名留空并在报表标“未知渠道” |
| 组织移动导致历史口径争议 | 明确“历史不回溯”，只影响新请求；账单快照冻结口径 |
| UI 范围膨胀 | 每个切片只交付对应页面；先功能后视觉打磨 |
| `degrade` 动作语义未定 | v1.1 只实现 `notify` / `disable`，`degrade` 预留并在 v1.2 定义（如降级到低成本模型） |
