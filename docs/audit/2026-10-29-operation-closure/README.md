# 现有功能操作闭环审查与修复（2026-10-29）

基线：`6c9c0dc`，结果对应本轮工作区修改。审查依据当前实际提供的功能，沿“入口 → 配置/提交 → 生效 → 使用 → 结果核验 → 停用/清理”检查，并直接修复已复现的断点。

本轮修复 16 组操作断点。最终全量 Go 竞态测试、前端 728 项测试、真实 PostgreSQL/Redis 集成、双副本空库启动及浏览器验收均通过。机器可读结果见 [evidence.json](evidence.json)。

## 1. 已修复的断点

| 编号 | 原来的断点 | 修复后的操作 |
|---|---|---|
| CP-01 | 注册页、注册弹窗、管理员新建用户均忽略后端返回的初始 API 密钥；关闭响应后无法再找回 | 统一展示一次性密钥，明确保存后继续；复制失败可手动选择；密钥保留在内存中 |
| CP-02 | Playground 先收到空密钥列表时会永久保留无凭证默认值，即使稍后已加载密钥 | 未手动选择时接入晚到的密钥；保留用户明确选择的公开调用；创建用户后刷新工作台数据 |
| SK-01 | Skills 演练没有网络请求，定时器直接输出成功及虚构的工具执行跟踪 | 使用保存的 SKILL.md 和输入任务进入 Playground，真实发送模型请求并沿用审计、扣费；界面说明本地工具任务由接入客户端执行 |
| SK-02 | 技能保存 API 支持更新，控制台没有编辑入口 | 增加编辑入口，保留技能 ID、启停态与元数据，修改后可下载新工件并实测 |
| SK-03 | 任意技能 ID 可进入 ZIP 根路径、HTTP 路径和客户端安装命令；自动 ID 仅精确到秒 | 技能/MCP ID 在控制面和仓储共同校验，仅接受安全的单段标识；自动 ID 使用随机账务标识生成器避免同秒覆盖 |
| MC-01 | 每次读取 MCP 列表都会重新播种并覆盖内置服务配置；删除的内置服务也会重建 | 初始播种与完成标记在同一事务中提交，已有记录不覆盖；后续读取、重建 Repository 均保留编辑和删除结果 |
| MC-02 | 导出的本地服务配置固定使用 npx，遗漏参数；运行时用空格切分命令并忽略 env_vars | 前后端正确保留运行程序、引号内参数与空参数；环境变量以字符串 JSON 校验并传入子进程；客户端配置包含相同参数与环境 |
| MC-03 | 客户端配置把网关 API Key 同时发送给外部 MCP 地址 | 网关凭证仅配置在网关连接，外部服务保留自己的认证边界 |
| MC-04 | MCP 无编辑入口；手工指定且不以 custom- 开头的 ID 没有删除按钮 | 可编辑服务并保留 ID、禁用态和元数据；外部服务按服务身份提供删除操作，支持 HTTP transport 配置 |
| MC-05 | 探针固定标 HTTP 200，工具 isError 仍显示成功；选择具体服务时 discover/list 实际查询的是聚合网关；部分连接检查伪造在线与 1ms | 展示实际 HTTP 状态和工具错误；明确 discover/list 的聚合目标，具体服务默认进入真实 tools/call；取消本地伪造延迟，非 2xx 不报告在线 |
| MC-06 | 原生 MCP 服务关闭后仍能列出和调用工具；已禁用技能仍可按 ID 读取执行指引 | 工具发现和实际调用共同检查原生服务开关；技能 inspect/manifest 拒绝禁用状态；重新启用后恢复 |
| SP-01 | CSV 导出只保留四位小数，极低单价归零；防公式转义回填后变成新的渠道/模型 | 导出保留存储的九位精度；转义前导单引号并在回填时还原，连续导入不新增重复身份 |
| SP-02 | CSV 逐行提交，后续数据库写入失败会留下已成功的前半批 | 全批校验后在一个事务中 upsert；SQLite 触发器和 PostgreSQL 约束故障均验证整批回滚 |
| SP-03 | 超限文件只截断前缀，可能导入一个看似完整的子集；微小负数可能先被舍入为零 | 明确拒绝超过 2 MiB、空文件、非法数字、负数和越界价格；无效文件不写入有效前缀 |
| SP-04 | 前端直接导入 CSV、丢弃逐行错误；供应商状态不能编辑；缺失报价不进入对照表 | 上传先调用 dry_run，展示逐行错误或预览，确认后再提交并刷新；可维护启停态和价格；缺失报价显示“未配置”，不按零计算价差 |
| HA-01 | 双副本首次启动时，后启动副本的迁移 advisory lock 继承请求连接的 500ms lock_timeout，直接退出 | 使用非阻塞 advisory lock 重试，启动等待上限为 2 分钟；请求连接超时保持原有配置；取消或失败时丢弃可能持锁的物理连接 |

控制面相关文件同时按职责拆分：MCP 配置、修改、探针分开；技能管理和工件下载分开；供应商 CSV 与单条维护分开。

| 多模态 | 图像、TTS、STT、视频异步任务、Embedding、Rerank 的既有受控上游集成全部随全量测试通过 |
| 售价和计费 | 分组、通配符、缓存、分时、币种、结算幂等既有回归；上游报告 1000 输入/500 输出，以 2/4 元每百万 tokens 定价，实扣每次 0.004 元 |

| 供应商报价 | 九位精度、转义标识、禁用态导出回填；数据库错误回滚；浏览器上传、预览期间不写入、确认提交及列表刷新 |
| Skills | 新增、编辑、ZIP 内容及 ETag 更新；禁用技能拒绝运行时读取；浏览器带 SOP 和任务进入 Playground，核对实际请求体与流式响应 |
| MCP | 命令引号/环境变量的真实子进程握手；远程 HTTP initialize → initialized → tools/call；双节点启停；浏览器真实探针响应与错误显示 |
| 控制台导航 | 浏览器逐一进入 dashboard、channels、models、logs、reconciliation、wallet、keys、users、docs，未出现错误边界或未捕获页面异常 |

## 4. 验收边界

运行验收使用独立 Compose 项目、临时 PostgreSQL 数据库、独立 Redis DB 和受控上游，与现有部署的数据分开。结果证明网关和控制台在这些可重复场景中的操作闭环。

临时验收容器与网络已清理；现有两个网关、PostgreSQL、Redis、对象存储仍为 healthy，负载均衡器正常运行。
