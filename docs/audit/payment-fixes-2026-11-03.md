# 支付修复：2026-11-03

按[支付审查](payment-review-2026-11-02/README.md)修复全部六项问题和兼容性事项。模拟充值的接口、实现、环境开关和状态展示已删除；支付流程直接使用新的约束，不提供旧请求或旧订单入账分支。配置和运行规则见 [PAYMENTS.md](../PAYMENTS.md)。

| 原问题 | 实现与验证 |
| --- | --- |
| 沙箱免支付入账 | 删除 GET/POST 模拟充值路由、处理器及 ops 开关；实际路由测试确认请求返回 404、余额不变 |
| 退款与拒付未处理 | 保存原始调整对象、金额、币种及钱包预留额，核验当前退款/争议状态后在事务中调整净余额；覆盖部分/全额退款、失败释放、争议胜诉、不同币种、超过原金额、负余额及迟到通知 |
| 漏通知无补偿 | 返回页主动核验，保存失败通知，后台定时恢复订单与事件；覆盖故障恢复、通知早于付款事件及进程退出后未绑定 Session 的延迟通知 |
| 创建会话缺少幂等与恢复 | 先保存订单；用户与幂等键唯一约束、稳定 Stripe 幂等键、固定创建参数、当前会话重新查询；响应丢失/写入失败按订单引用恢复，不重复生成会话 |
| 部署不传支付配置 | Swarm 显式透传；Helm 使用支付 Secret 与公网地址参数；Kubernetes 支持独立支付 Secret |
| 测试支付混入生产 | 校验模式、密钥、事件及 Session 环境，数据库绑定支付模式；关闭支付也不能绕过数据库模式检查 |
| API、最低金额与回跳 | 请求与通知固定 `2026-10-28.endive`；线上最低金额可配置并传给前端；同源自定义回跳自动携带订单上下文 |

入账、退款和争议由同一个服务端核验路径处理。数据库租约覆盖远端查询和事务提交，版本号拒绝已失效的核验结果。SQLite 与真实 PostgreSQL 共用仓储测试，覆盖 64 次并发完成同一订单、32 个订单并发入账、旧租约不得覆盖退款、钱包失败回滚、请求幂等、事件去重、环境绑定和兑换码并发。

已将原审查的临时缺口演示转换为正式测试；原始复现 JSON 仍保留为审查基线。新的 PostgreSQL 脚本只使用临时容器和临时数据库，不操作部署中的数据库。

验证全部通过：Go 全量竞态回归（16 个包含测试的包）、`go vet`、75 个前端测试文件的 746 个用例、前端检查与生产构建、真实 PostgreSQL 的 7 组支付场景，以及 Helm/YAML 验证和缺少支付 Secret 时拒绝渲染的检查。结构化结果见[验证记录](payment-fixes-2026-11-03.json)。

本次没有实际 Stripe 账号或交易，未部署到线上。托管 Checkout、商户币种能力、3DS、公网通知及实际退款往返需后续在独立 Stripe 测试环境验收。
